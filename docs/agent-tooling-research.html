コーディングエージェントの実行環境とレビュー基盤

mac-mini のローカルで herdr を動かし、ghq_root 配下の各 repo で Claude セッションを起動して、そこを唯一の起動点として運用している。 モバイルからは Claude の Remote Control で操作する。この構成を orca へ移すか、server を自宅鯖 marujirou へ移すかを決めるために調べた。 あわせて、diff レビューで人間とエージェントがどこまで対話できるかと、orca が Claude Code に入れる hook が何をしているかを追った。
結論

当面は herdr local と orca local の並行利用を続ける。server の marujirou への移設は今はしない。

diffo だけ導入を検討する。diff レビューで人間とエージェントが双方向に対話できるのは、調べた範囲では orca でも hunk でもなく diffo / diffler / diffing の系統だけだった。そのうち diffo は Claude Code の背景タスクで待たせる運用が skill に書かれていて、いまのセッションの使い方にそのまま乗る。

移設を保留する理由は、remote にすると失うものが構成ごとにはっきりしているため。herdr なら URL を開く先とテーマ、orca なら client 切断中の orca コマンド全滅。
いま困っている点がそれに見合わない。移す判断をするときの材料は下にまとめてある。

双方向にすると必ず現れる 3 つ

  • 作者フィールドがデータモデルに入る — Author = 'reviewer' | 'agent' (diffo)、wroteBy (adiff)。区別しないなら返信の意味が無い
  • エージェントが待つ機構が要る — wait_for_feedback (diffler)、diffo poll、await-review (diffing)
  • resolve の権限をどちらに置くかが設計判断になる — diffler・diffo は人間専用でエージェントは提案まで。diffing・remarque・adiff は双方に許す

待ち方の設計 (diffo)

diffo poll は HTTP long-poll でプロセスとしてブロックする (30 分固定、変更手段なし)。ただし skill が待ち方を明示的に指定している24。

引用: DiffoHQ/diffo の skills/diffo/SKILL.md

Don't let it block the conversation either.

prefer a harness-native tracked background task

whose completion is guaranteed to resume THIS session

Claude Code の Bash run_in_background がこれに該当する。待っている間も同じセッションで別作業ができ、feedback が来た時点で再開される。

poll が 30 分で切れたら {"status":"timeout"} を出して exit 0 する。feedback は失われず、キューはサーバの再起動でも復元される。次に poll を張ったとき、既に未配送があれば待たずに payload が出る25。

人間が通知するパターンも設計に入っている。エージェントが繋がっていないとき、各スレッドに Copy prompt ボタンが出る。UI はエージェントの presence を waiting / listening / working で常時表示する。
Send が生きたエージェントに届くのか、キューに入るのかを人間が見て判断できる26。

複数行コメントは人間だけができる。anchor は endLine?: number を持ち、UI ではドラッグ選択・shift-click・chip の ▲▼ で範囲を動かせる。
ただし CLI に範囲のフラグが無い。エージェント名義では単一行かファイル全体か changeset 全体しか選べない27。

当面やること、保留すること

やる

  • herdr local と orca local の並行利用。両者は同じ層で競合するが、orca は HTML preview と diff ビューアを持ち、herdr はターミナル中心の多重化に強い。どちらかに寄せる判断は、しばらく使ってからにする
  • diffo の導入検討。npx -y @diffohq/diffo で試せる。repo には何も残らず、状態は ~/.diffo/diffo.db に入る。skill と plugin が同梱されている

保留する

  • server の marujirou への移設。手段は揃っている。herdr なら herdr --remote marujirou の 1 コマンドで済む (~/.ssh/config に Host marujirou が既にある)。orca なら SSH target の登録から。marujirou 側の追加準備は Node 18 以上の導入だけ
  • 移す判断をするときに効く材料: 表 1 の境界 (何が手元に残るか)、表 2 の導入コスト、そして orca SSH の弱点 (client 切断中は orca コマンドが全滅する)

生成に関する補足（判断には不要）

読み飛ばしてよい。確からしさの判定に要ること。

  • marujirou と mac-mini の実測値は 2026-08-31 から 09-01 に ssh とローカルで取得した。ホストの状態が変われば古くなる
  • orca・herdr・hunk・diffo のいずれも実機では動かしていない。docs と実装の読み取りのみ
  • orca の画像プロトコル対応は「docs に記述が無く、依存パッケージに画像アドオンが無い」ことからの推定
  • orca remote での OSC 52・システム通知の帰属、scrollback の保持上限は docs に記載が無い
  • diffo の HTTP エンドポイントと SQLite の直読みは実装からの読み取りで、実行して確かめていない
